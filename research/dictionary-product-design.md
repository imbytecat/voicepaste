# 单一启用渠道下的独立词库设计

设计日期：2026-10-04。状态：目标设计与实施记录，不是所有功能已完成的声明。用户最终决定：只启用一种渠道，服务功能完全独立，不保留旧格式兼容。当前已实现渠道隔离及火山词库管理；豆包官方词库仍受实际访问与写入语义验证阻塞，不以本地替代方案冒充完成。

## 1. 决策

**用户选择一种完整的使用方式：豆包输入法，或火山引擎 API。同一时间只启用一个渠道，界面和后台都只运行该渠道的功能。**

- 初次设置二选一；以后允许在“使用方式”入口明确切换，但不支持双开、并行管理另一渠道或自动故障转移。
- 不建立全局主词库、跨渠道复制或同步入口，也不建立通用 `DictionaryProvider.sync()`、插件注册表或通用同步引擎。
- 火山管理自己的 Key、ASR 云热词表、识别和文本处理设置；豆包管理自己的账号、官方个人词库、识别和文本处理设置。两者不共享配置值、身份、词条、绑定、同步游标、删除策略和验证规则。
- 未选渠道只保留已保存的本地配置和安全凭据，不主动校验、不联网、不刷新词库、不轮询登录，也不因其凭据缺失或配置错误影响当前渠道。
- 词库不是仅供编辑的文本框：支持的渠道必须完成“词条写入→服务确认→识别实际使用”的闭环。只保存到本地、账号已登录、连接测试成功，都不等于词库已经可用。
- 豆包的正式目标包括读取和管理官方账号词库，并验证它如何参与 ASR；不得用 LLM 事后替换、硬编码纠错或仅本地保存冒充此目标。
- 基础听写不强制使用词库。游客可以继续使用豆包语音；本方案的豆包账号词库需要登录。游客自定义词是否存在独立可用路径尚未验证，不承诺也不先实现第二套“游客词库”。

### 为什么保持渠道完全独立

火山的受管理词表和豆包手机/电脑共享的个人词库没有相同的所有权。统一主词库、双标签管理和跨渠道复制都会让用户同时面对两套身份与状态，没有必要。软件只展示当前选择的完整方案；切换时停用旧方案、启用新方案，不搬运数据、不触发另一渠道的功能。

## 2. 已确认事实与技术前提

| 项目 | 已确认 | 不能据此推导 |
| --- | --- | --- |
| 火山词库 | 已有查询、创建、更新、删除受管理词表及 ASR 引用表 ID 的实现 | 所有火山账户词表都归 VoicePaste 管理 |
| 豆包账号语音 | 官方扫码会话、身份校验、账号和游客音频识别均已实测 | 登录后自动使用了个人词库 |
| 豆包官方个人词库 | 官方隐私政策 2.7 明确账号跨设备同步；2.3 说明云端语音可能结合个人词库和常用语实体 | VoicePaste 已掌握完整同步或语音个性化契约 |
| 豆包同步协议 | 样本中有同步开关、版本、上传、推送、拉取及独立 WebSocket 实现 | 词条结构、删除墓碑、并发版本条件、压缩/签名和幂等性已恢复 |
| 豆包语音上下文 | 样本中存在 `user_words`、`modify_pair`、`ner` 及相关上下文请求 | 任意 `Vec<String>` 可以直接提交，或者这些接口就是官方个人词库 CRUD |

**实现前置门槛：**先在明确授权的可控测试账号/词条上证明豆包“账号词库→语音上下文→ASR”的关系，以及完整、安全的读写语义。若只有只读能力，不能宣称可管理；若不能证明使用词库，不能宣称词库识别已生效。遇到此类缺口，应报告具体阻塞并讨论范围，不能把禁用按钮或本地文本框当完成。

官方有此功能不等于开放了第三方集成契约；本方案继续按实验性、非官方协议接入披露，不承诺永久免费、稳定或与官方客户端效果一致。

## 3. 信息架构与页面

沿用现有设置布局，唯一渠道选择入口为“使用方式”。选择后，只显示该渠道的账号或 Key、词库及已验证可用的服务功能。

| 页面 | 内容 |
| --- | --- |
| 使用方式 / 语音识别 | 豆包与火山单选；选定后展示其专属设置、连接测试和试说，另一渠道不挂载功能面板 |
| 词库 | 只显示当前渠道的词库；豆包为个人词库，火山为常用词；没有渠道标签或另一词库入口 |
| 文本处理 | 只显示当前渠道的处理配置；可选 LLM 的开关、模型、提示词和凭据按渠道独立，不继承另一渠道的设置 |
| 语音输入 / 应用 | 麦克风、快捷键、触发方式、浮层、窗口和更新等应用级设置；不是某个 provider 的功能 |

共用的是录音、快捷键、粘贴等基础实现及视觉组件，不是服务配置或数据。某渠道不具备的功能不显示一个假开关，也不借另一渠道补齐。

### 当前选择豆包时的页面示意

以下为设计示意，数量和状态不是当前账号数据。

```text

豆包个人词库
```

切换为火山后，账号区域替换为火山 Key，词库页替换为火山常用词，处理设置切换为火山自己的配置；界面不同时保留另一套功能入口。

### 关键交互

1. 当前启用渠道是唯一依据，没有独立的“正在管理另一渠道”状态。词库、连接测试、试说和文本处理都跟随它。
2. 切换前处理旧渠道未保存的设置与词库草稿：保留到旧渠道、明确放弃，或取消切换；不能自动上传草稿。
3. 未配置好所选渠道时，只提示完成该渠道的账号或 Key 配置。另一渠道即使可用，也不自动接管。
4. 词库独立保存。全局设置的“保存”不再隐含上传词条；页面区分“保留本机草稿”和“应用到当前服务”。编辑先更新内存草稿，“保留草稿”只写本机，“应用”先可靠保存草稿再请求远端。关闭设置窗口前，有未落盘修改则提示保存、放弃或取消；落盘失败不承诺异常退出后可恢复。
5. 列表支持搜索、单条添加/编辑/删除、批量选择；导入导出先支持 UTF-8 TXT，每行一词。导出是用户选择的文本文件，不是渠道间互通功能，也不包含官方权重、学习统计或同步元数据。
6. 导入先预览新增、重复、非法、超限项。默认追加，不默认替换；不悄悄截断。只按当前渠道验证与应用，不读取另一渠道的词库作为导入源。
7. 控件支持键盘操作和可读标签；状态不能只靠颜色。错误定位到具体草稿行，计数与完整变更预览可见。
8. 不提供“所有渠道一键清空”“退出时删除云词库”或跨渠道复制、合并、同步入口。

## 4. 两个渠道的专属行为

### 4.1 火山引擎

- 标题：火山常用词；身份为当前已保存 Key 对应的服务资源，界面不泄露 Key。
- 复用现有 `hotwords::inspect/sync` 和受管理词表逻辑。不修改其他应用的词表；存在多张无法确定归属的候选表时不擅自接管。
- “听写时使用常用词”只决定识别请求是否引用表 ID，不创建、清空或删除云端词表。
- “应用到火山”展示新增/移除数量，检查云端变化，再执行创建或更新。最后一条被删除时，明确提示将删除 VoicePaste 管理的词表，不能藏在普通保存动作中。
- 词数和单词限制使用已验证的火山规则与服务返回限制。现有界面有 10 字素/30 UTF-8 字节等校验；不要把这些数值复制给豆包，也不能只用前端字符数当后端字节限制。
- 更换 Key 视为新的目标配置：旧云表不删除，旧绑定不能盲目套用；先检查新目标，再让用户确认是否将原词条复制过去。同账户换 Key 也不能仅靠昵称或 Key 外观推定同一资源。
- 云端发生修改时复用差异展示，但改善当前二选一流程：默认先审阅差异，可保留云端并重放本机明确修改；“以本机整体覆盖”仅对明确归属的受管理词表提供，并单独确认。

### 4.2 豆包输入法

- 标题：豆包个人词库；身份为当前经过输入法服务验证的账号，不是昵称、不只是当前 token 字符串。
- 未登录时显示“登录后管理豆包个人词库”，明确“游客语音仍可用”。登录不自动开始词库读取或上传；首次进入账号词库功能时单独说明访问范围并由用户主动连接。
- 默认读取当前账号官方个人词库，保留服务端记录 ID、版本及必要元数据；UI 展示词条文本，不把官方数据降格成一个全量覆盖的字符串数组。
- 新增、编辑、删除按确认过的官方变更协议执行；对已有条目的编辑保留非文本元数据。删除必须确认会影响同账号其他设备，不能声称只是“从本机隐藏”。
- 不默认清空、重建或接管官方个人词库。不自动导入通讯录、常用语、屏幕文本、输入历史或剪贴板；这些不是接入个人词库的附带授权。
- “个人词库”“常用语”“语音上下文”保持不同概念。本轮完整目标是个人词库；不把常用语正文直接当热词提交，也不顺便实现短语展开或键盘学习。
- VoicePaste 自己的读取/刷新许可与官方账号的全设备同步开关不同；不能用 `sync/settings` 的总开关实现“在 VoicePaste 中启用词库”。若官方隐私设置阻止访问或使用，解释原因，不自行替用户开启。
- 对“听写时使用个人词库”的开关，必须先验证客户端确实能控制。若服务端随账号自动应用且无法独立关闭，显示真实说明，不放一个无效开关。选择不用账号需用户明确退出，不能后台变成游客。
- 词库接口权限不足或暂不可用，只影响词库能力；不能仅凭词库接口拒绝就判定语音账号过期。只有身份校验明确失效，才进入重新登录流程。

### 4.3 官方同步与语音上下文如何衔接

必须先实测确定以下哪一种是真实契约，而不是在产品中堆三个“兼容模式”：

1. 官方个人词库同步成功后，ASR 直接按账号使用；则只保持账号与词库关联，不重复上传语音词表。
2. 官方词库与语音上下文需要显式桥接；则在豆包专属实现里处理已验证的词条投影/上下文更新，并分别确认“词库同步”和“语音上下文准备”状态。
3. 目前只能操作语音上下文，无法安全管理官方个人词库；这是目标阻塞，不是完成。不能将临时上下文命名为“已同步手机词库”。是否另做本机自定义词功能须明确改变交付范围，不能暗中替换本方案。

任何情况下都不为补齐这条链路去调用可能清除整份上下文/词库的登录、退出或初始化接口。

## 5. 单一启用渠道的切换与隔离

### 切换语义

唯一选择不等于终身锁定：用户可以明确切换，但切换完成后只有新的渠道可执行服务操作。

1. 录音、试说或云词库提交进行中，先结束操作再切换。待发送的工作可以取消；已发出的写入不能假装已撤回。结果不明时保留旧渠道的未决记录，不为处理它在后台继续使用已停用渠道。
2. 处理旧渠道草稿，停止其可取消请求、词库连接、刷新及登录轮询。取消未完成登录按原账号流程恢复此前身份；切换不等于退出已登录账号或删除旧 Key。
3. 原子保存新的唯一渠道选择并更新活动代次，随后才允许新渠道操作。持久化失败时不显示已切换；旧选择仍有效，需要时只恢复它的本地运行状态，不自动重试远端写入。
4. 新渠道缺少配置或凭据不可用时，显示该渠道待配置或错误状态。不会继续用旧渠道录音，也不会自动回退。
5. 再次切回时恢复该渠道自己的已保存配置，并按需重新校验其身份与词库。恢复草稿不自动上传；恢复连接证明不能复用上次的过期成功状态。

### 隔离不仅发生在界面

- 前端只挂载活动渠道的功能与副作用，不让被隐藏的面板继续运行账号查询、词库刷新或连接测试。
- 后端对服务命令同时验证窗口权限和活动渠道；直接调用非活动渠道命令同样拒绝，不能仅靠隐藏按钮。
- 请求和事件绑定渠道、身份、活动代次及相应数据版本。切换后的旧响应不能改变新渠道的状态、词库或成功提示；必须保留的旧提交结果只能归入原渠道的本地未决记录，不能触发后续联网。
- 启动、唤醒和网络恢复只处理已选渠道；不为展示两张卡片而读取或校验未选渠道的凭据。未选渠道的旧格式或无效配置应原样保留并延迟校验，不重置、不阻止当前渠道使用。
- 每个渠道独立保存词库、草稿、使用开关、处理选项和凭据。普通设置保存只验证当前渠道及应用级配置，不要求另一渠道“也配置正确”。
- 某渠道故障、账号过期、配额不足或词库不可用，只在该渠道提示。用户可以自行更换使用方式，但软件不将同一段录音发送给另一渠道。
- 应用级麦克风、快捷键、窗口、更新等保持共用；服务内功能的实现可以复用代码，但配置状态不得共享。可选 LLM 如继续保留，其配置和启用状态也按渠道隔离。

## 6. 保存、同步、识别使用：三件事分别展示

不要用一个绿色“已同步”覆盖所有状态。

| 维度 | 典型状态 | 说明 |
| --- | --- | --- |
| 草稿 | 无修改、已保留本机、保存失败 | 是否能恢复用户尚未应用的编辑 |
| 云端 | 未连接、读取中、已确认、有变更、冲突、结果待确认、失败 | 服务端数据是否已确认；显示最近确认时间 |
| 识别使用 | 未启用、将使用已确认版本、更新待准备、不可用 | 下一次会话实际采用哪种配置 |

建议文案：

- “草稿已保留在本机，尚未发送给豆包。”
- “云端已确认 126 个词；本机还有 2 项未应用。”
- “火山词表已更新，但本机确认信息保存失败；请重新检查，勿重复创建。”
- “提交结果待确认。先检查云端，再决定是否重试。”
- “豆包个人词库已同步，语音上下文尚未确认。”仅在真实契约需要两步时使用。

“已确认/将使用”不承诺每个词都必然识别正确；模型输出具有不确定性。连接测试只证明基础 ASR，不给词库加成功状态。

### 应用流程

1. 确认目标就是当前启用渠道，固定其活动代次、身份、草稿版本及读取云端时的基准。
2. 本地校验；将草稿与待执行动作可靠落盘。落盘失败时不开始远端写入。
3. 重新读取云端或使用已验证的条件版本，检查冲突。用户审阅的变更不能因后台刷新偷偷扩大。
4. 提交渠道专属变更，确认服务端接受并核对结果；如果还要准备语音上下文，继续该渠道必要步骤。
5. 本地提交确认快照、绑定、云版本及草稿完成状态，最后更新 UI。

不做自建通用离线任务队列。只保留各渠道自己的草稿、基准和必要未决动作；断网或重启后，仅在该渠道处于启用状态且用户进入相应功能时检查。不盲目重放可能已成功的新增/删除，不为已停用渠道后台联网。每个渠道的幂等标识或版本条件必须来自实际协议，不自行假设服务支持。

## 7. 冲突、失败和删除

### 冲突规则

- 比较“上次确认基准、本机草稿、当前云端”三者，而不是只比较词数。
- 云端无变化时应用本机明确修改；本机无修改时读取云端不构成覆盖请求。
- 不相交的新增/删除可以生成合并预览；同一记录的相反修改、删除后远端更新等必须交由用户处理。
- “合并”不是简单集合并集：并集会让已删除词条复活。豆包使用记录 ID、版本/墓碑等真实协议信息；火山可以基于文本集合和受管理表的基准做差异，但不能借此假设服务支持原子条件写。
- 只知道最终快照、无法解释删除来源时，不做自动破坏性合并。
- 协议无原子版本条件时，读后写存在竞态。对共享豆包词库，若不能保留未知记录并避免覆盖并发修改，禁止开放全量写入；单次“读取再 PUT”不算冲突安全。

### 失败处理

| 情况 | 行为 |
| --- | --- |
| 离线编辑 | 可手动保留本机草稿，显示未上传；联网不会无提示发布 |
| 云端读取失败 | 展示带时间的已有快照，保留草稿；不把缓存说成最新数据 |
| 提交前失败 | 草稿保持待应用；已确认的旧配置不被清空 |
| 请求发出后超时/回读失败 | 标记结果待确认，先查询；不假定远端没写入，不自动重复新增 |
| 远端成功、本地确认失败 | 保留未决状态，下一次检查恢复；不尝试用旧快照覆盖远端作为“回滚” |
| 词条超限或非法 | 指明条目与目标渠道限制；不静默截断或只上传一部分 |
| 刷新时用户继续编辑 | 不覆盖新草稿；结果只更新对应基准或提示冲突 |
| 账号/Key 在请求期间变化 | 旧结果不得更新新目标的 UI、绑定或成功状态；旧远端可能已提交的事实仍需保留 |
| 配额/权限不足 | 提示具体词库问题，不删除账号、词条或切换服务 |

### 删除和身份操作

- 关闭词库使用、换 provider、退出账号、删除本机缓存，都不删除云端词条。
- 火山最后一条删除会涉及受管理云表删除，明确确认；豆包删除的是共享账号中的指定记录，显示跨设备影响。
- 不提供豆包全账号词库清空捷径，不把关闭同步当成删除。
- 退出豆包时先处理未应用草稿：保留登录继续编辑、导出后退出、或明确丢弃并退出。没有成功导出就不能把“导出后退出”当成功。
- 确认退出后清除该次账号连接的本地云词库缓存和待应用草稿，不读取或修改火山数据，不调用云端清空接口。单纯切换到火山不执行此退出清理。
- 应用写入期间串行化账号/Key 切换和退出；需等待或取消未发出的工作。不能声称取消网络请求就撤回了已经提交的云端变更。

## 8. 身份与数据结构

沿用现有本地存储与系统凭据库，不引入数据库、云中转或新账号系统。

| 数据 | 所有者与保存位置 | 关键约束 |
| --- | --- | --- |
| 当前识别 provider、麦克风、快捷键 | 现有应用设置 | 不决定其他渠道词库的所有权 |
| 火山使用开关、确认词条、云表绑定 | 当前火山配置，现有本地存储 | 草稿与上次确认数据分开；Key 变更要重新确认目标 |
| 火山 Key | 系统凭据库 | 不把 Key 或可复用认证数据放进词库文件 |
| 豆包 token、验证过的主体 ID | 系统凭据库中的账号会话 | token 可轮换、昵称可更改，均不能充当词库身份 |
| 豆包词库快照、草稿、同步元数据 | 当前账号连接对应的本地记录 | 关联后端生成的不透明 owner ID，前端不需要原始 UID |
| 未决提交 | 对应渠道的本地记录 | 足够恢复一次未完成确认，不是无限任务队列 |
| 渠道内文本处理配置及其凭据 | 各渠道自己的设置与凭据条目 | 开关、模型、提示词等互不继承；凭据留在系统凭据库 |

### 豆包账号身份补齐

当前 `Session` 仅保存 token、nickname、expired；校验响应中的有效 `user_id` 被检查后未保留。词库接入需要保留已验证的规范化主体 ID，并给这次账号连接分配持久的不透明 owner ID。

- 同一主体的 token 轮换、重启恢复，继续使用同一个 owner ID。
- 主体发生变化，不能继承旧快照、草稿或同步游标。
- `account.revision` 继续隔离进程内异步状态，但不能代替持久账号身份。
- 退出时移除会话与该 owner 的词库缓存；重新登录可重新生成 owner ID 并从云端读取，不为此建设多账号档案管理器。
- 只接受当前会话结构。缺少必要主体信息或版本不受支持时，保留原凭据并明确报错；用户需主动退出后重新登录，不补写旧会话、不猜 UID、不拿昵称匹配。

火山在 Key 变化时同样更新配置代次并重新确认绑定。无法取得可靠账户/资源标识时，保守视为目标改变，不声称识别出“同账户换 Key”。

所有词库命令在后端校验来源窗口、活动渠道、活动代次、当前身份和操作版本；不能信任前端传来的 provider、owner ID、云表 ID 或 record ID 来获得对其他渠道或身份的操作权限。云响应需限大小、验证类型，遇到未知协议版本停止写入。

## 9. 与真实听写的融合

- 每次开始听写固定唯一活动 provider、活动代次、身份、使用开关及已确认绑定/上下文配置。录音期间不切换渠道、不修改同一目标词库；现有 idle gate 可以沿用，不另做全局调度框架。
- 不在每个音频分片查询或上传整份词库。火山继续发送表 ID；豆包按已证明的官方契约处理。
- 本地草稿不参与识别。云内容待确认时不能标为“将使用最新词库”；若不能确定可用配置，要求先检查或由用户明确停用可控的词库能力，而不是静默丢掉词库。
- 本地尚未提交的草稿不阻止使用同身份已确认版本。已发送但结果未知的写入不同于纯本地草稿，必须先解决不确定状态。
- 冻结本地绑定不等于能冻结其他官方设备的修改；不承诺云端词库在整段录音期间不可变。
- **试说与正式听写使用同一已应用词库配置。** 仅结果去向不同：试说不运行 LLM、不粘贴。已移除原先 `!is_preview` 排除火山热词表的条件，改为共用已确认词库选择逻辑；实际云端效果仍需有效火山 Key 验收。
- 试说只能使用当前活动渠道，不支持暗中测试另一渠道。新草稿需要先应用，不能为了试说偷偷临时上传，也不能发送给另一渠道。
- 如增加有词库/无词库对照，仅在服务确实支持会话级控制时提供；不为获得对照而偷偷退出账号、换身份或清空云词库。
- 热词成功不以单句是否出现词条作为唯一依据：确认服务接受、识别请求引用正确，并用可控专有名词音频验证效果。保留真实错误，不通过 LLM 或字符串替换凑命中率。

## 10. 实现位置与最终结构

### 复用与改动

| 位置 | 设计中的职责 |
| --- | --- |
| `src-tauri/src/hotwords.rs` | 保留火山具体协议与冲突判断，不改造成通用 provider trait |
| `src-tauri/src/doubao_account.rs` | 增加稳定主体与 owner 关联，继续负责账号生命周期，不放入词库协议 |
| 豆包专属词库模块（实现时新建） | 官方记录、版本、变更、同步和必要语音上下文；结构必须依据验证结果确定 |
| `src-tauri/src/lib.rs` | 命令授权、活动渠道和代次检查、idle gate；非活动渠道命令拒绝；普通 `save_settings` 不再写云词库 |
| `src-tauri/src/settings.rs` | 分别保存渠道完整配置、确认数据与草稿，隔离凭据；只校验当前渠道，不使非活动配置故障扩散 |
| `src/components/Settings.tsx` 及词库页面 | 唯一使用方式选择；只挂载当前渠道功能，移除双词库标签与跨渠道操作 |
| `src/hotwords.ts` | 复用明确适用的差异和展示工具；火山格式限制仍属火山，不强行推广 |
| ASR、文本处理及 `RecognitionSpeechTest.tsx` | 只消费活动渠道配置；正式听写和试说引用相同的已应用词库配置 |

可以复用列表、搜索、导入预览等已有或确有两个使用者的 UI 行为，但暂不抽取完整通用编辑器接口。协议对象始终留在对应渠道。

### 仅支持最终结构

1. 产品只读写当前 schema 3 配置、渠道专属凭据和当前账号会话结构，不保留旧格式转换器、迁移标记、旧 Key 别名、运行时兼容层或兼容测试。
2. 不支持的配置应在访问服务前明确拒绝，原文件不自动覆盖；不支持的会话保留原凭据，直到用户明确退出。无需向后兼容不等于允许静默丢数据。
3. 新配置下，各渠道的数据独立保存；切换、关闭词库和普通设置保存不产生云词库写入。未选渠道的损坏配置延迟至选中时报告，不替它自动修复或清空。
4. 词库应用与普通设置保存彻底分开，只保留一套实际调用路径。原子本地保存、凭据写入失败回滚和未决云提交恢复属于当前功能的数据安全，不属于兼容层，必须保留。
5. 两个渠道的 LLM 默认各自关闭、凭据各自配置，不从旧全局设置或另一渠道复制。旧本地数据的备份与重新配置由用户明确处理，不引入常驻迁移工具。

## 11. 实施顺序与完成条件

这是依赖顺序，不是把完整目标缩减为若干禁用界面的理由。

### 第一阶段：豆包协议与效果验证

- 确认词库读取的身份、分页/增量、记录 ID、版本、删除和元数据语义。
- 区分同步开关、词库内容同步与语音上下文；确认所需凭据与权限，不复用错误类型的 token。
- 先读取并保全基准，再在用户明确授权的专用测试数据上完成新增、修改、删除、重复请求及冲突验证；不得拿真实词库做全量覆盖实验。
- 验证官方客户端和 VoicePaste 间双向可见，并证明词条进入真实 ASR；账号身份成功不能替代这项检查。
- 如果缺安全写入或语音使用契约，停在明确的技术阻塞，不伪装完成。

### 第二阶段：独立词库生命周期与最终结构

- 从普通设置保存拆出火山词库应用；当前结构内的数据安全保留，不实现旧格式迁移。
- 增加豆包账号主体关联及专属词库实现，完成草稿、确认快照、未决结果与退出清理。
- 修正词库试说与正式听写不一致的问题。

### 第三阶段：单一启用渠道的完整体验

- 唯一使用方式选择；词库、账号/Key、文本处理只呈现当前渠道，不保留双标签管理或跨渠道复制入口。
- 完成切换隔离、重新登录、换 Key、离线、重启、并发修改与权限失败路径。
- 依据真实数据流更新 `README.md`、`PRIVACY.md`，尤其词库读取缓存、写入、跨设备影响及未选渠道不活动的规则；不提前修改现行隐私声明来描述尚未实现的行为。

## 12. 验收标准

### 必须可观察的用户行为

1. 只接受当前配置和会话结构，旧格式在服务调用前被明确拒绝且原数据未覆盖；新结构内切换渠道、关闭词库及普通设置保存均不产生云词库写入。
2. 始终只有一个活动渠道；词库及服务设置只显示它的数据。切换可保留旧渠道本地草稿，但不会上传或带入新渠道。
3. 火山添加专有名词后，云端确认、正式听写和试说引用同一表；关闭使用不删除云表。
4. 豆包登录后主动连接可读取真实官方词库；授权的测试词条新增、编辑、删除可在官方客户端和 VoicePaste 互相确认，其他词条及必要元数据不变。
5. 豆包词条真实参与账号 ASR。关闭 LLM 验证原始结果和必要请求关联；记录服务实际差异，不承诺模型百分之百命中。
6. 未登录豆包可以基本听写，但不会把缓存账号词库用于游客，也不会宣称游客词库已生效。
7. 没有跨渠道复制、合并、同步或非活动渠道试说入口；导入仅接受用户明确选择的文件并按当前渠道处理，不读取另一渠道词库。
8. 超限、非法词及重复项被准确列出；没有静默截断、遗漏或无提示全量覆盖。
9. 本机与云端同时修改时能看到差异；删除词不会因简单并集合并而复活。
10. 模拟“服务已接受但响应丢失/回读失败”，重启后先核对，不重复新增、不把未知状态显示为成功。
11. 模拟远端成功而本地落盘失败，用户看到部分成功与恢复动作，不覆盖远端以假装回滚。
12. A 账号请求延迟返回、期间尝试退出/切换到 B 时，B 不会显示或应用 A 的词条；刷新 token 不误判为新主体。
13. 退出账号处理未应用草稿后清除本机账号词库缓存；不删除官方云词库，不动火山配置。会话过期、词库权限不足和网络错误正确区分。
14. 录音期间本应用不提交同目标词库变更；试说不运行 LLM 或外部粘贴，但使用与正式听写一致的已应用词库参数。
15. 日志、错误和诊断不含原始 UID、账号 token、Key 或完整词条；普通配置与导出不泄露凭据。
16. 选择火山时，豆包账号过期、凭据不可读或配置无效，不阻止火山配置、启动、听写；反向同样成立。启动和网络恢复没有非活动渠道的请求。
17. 切换期间旧请求迟到，不能覆盖新渠道状态或发起后续旧渠道请求；直接调用非活动渠道命令被后端拒绝。
18. 切换后只使用目标渠道自己的识别与文本处理配置；另一渠道的 LLM 开关、模型、提示词和凭据不被继承。目标渠道未配置时不回退到旧渠道。
19. 录音、试说或写入进行中不能直接切换；结果未知的提交保留原渠道记录。切换选择持久化失败时，界面和后端都保持旧选择，不出现同时启用或显示与实际不一致。

### 工程验证

- 沿用现有测试工具，保留能抓住身份串用、删除复活、结果未知重放、部分成功和预览配置不一致的回归检查；不为字段转发或文案做机械测试。
- 实际启动 Tauri 界面验证编辑、应用、切换、冲突和错误恢复；仅通过前端 mock 不算完成。
- 网络协议验证必须有真实服务证据；模拟响应只能验证状态机，不能证明豆包协议可用。
- 实现完成后运行 `mise run check`，并记录各目标平台实际验证范围；不能以 Linux 验证冒充 Windows/macOS 已通过。

## 13. 明确不做

- 不以猜测的豆包协议写入真实词库，不以仅本地编辑或 LLM 纠错冒充官方词库接入。
- 不建双渠道同时启用或管理、跨渠道复制/同步/合并、跨服务删除传播、自动故障转移、账号档案管理、后台无限重试或持久任务框架。
- 不做通讯录采集、输入历史学习、键盘联想、常用语展开、剪贴板互传。
- 不把 LLM 强制纠错当 ASR 热词能力，不自动把整份词库发送给 LLM。
