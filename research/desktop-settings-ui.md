# VoicePaste 桌面设置页 UI 调研

> 调研日期：2026-08-07
> 目标：参考微信输入法近期桌面端设置与语音输入模式，把 VoicePaste 设置页收敛为简洁、低干扰的桌面偏好窗口。
> 约束：只采用微信输入法官网、官方应用商店页面、官方更新说明及候选组件库官方文档；不复制微信输入法品牌视觉资产。

## 1. 证据口径

- **直接观察**：第一方页面正文、更新说明或官方商店截图能直接确认的内容。
- **官方文字说明**：第一方页面明确描述的功能与行为，但不代表其具体界面长相。
- **推断**：根据直接观察提出的 VoicePaste 设计判断，不等同于微信输入法现有实现。
- **未确认**：第一方材料不能证明的内容；不使用第三方评测、媒体截图或用户视频补齐。

视觉证据需要额外区分：

1. [微信输入法官网](https://z.weixin.qq.com/)的“微信输入法桌面端”画面是**官方产品示意图**，可用于判断侧栏、内容区、留白等方向，不能用于还原真实像素规格。
2. [Microsoft Store 官方产品页](https://apps.microsoft.com/detail/xpfffp686ndrdz?gl=CN&hl=zh-CN)“屏幕截图 2/4”展示实际 Windows 设置窗口，是本文判断桌面信息架构与控件密度的主要视觉证据。
3. App Store 页面是 iPhone/iPad 产品页，不作为桌面布局证据。[Apple App Store](https://apps.apple.com/cn/app/%E5%BE%AE%E4%BF%A1%E8%BE%93%E5%85%A5%E6%B3%95/id1618175312)

## 2. 摘要结论

1. **微信输入法桌面设置采用“窄侧栏 + 单页内容”的偏好窗口结构。** Microsoft Store 截图可见左侧约五个任务分类，右侧只呈现当前分类；官网桌面示意图也使用同样的大分栏。它不是把全部设置堆成一条长页面。[Microsoft Store 官方产品页](https://apps.microsoft.com/detail/xpfffp686ndrdz?gl=CN&hl=zh-CN) · [官网](https://z.weixin.qq.com/)
2. **视觉“简洁”不等于信息稀少。** 实际设置截图在一个内容页中容纳多组单选、下拉框和开关，但通过浅色分组、统一行高、右对齐控件和极少装饰保持低噪声。
3. **语音输入正在从单纯转写升级为可直接使用的输入流程。** macOS 2.0.0 已支持长按 `fn`、实时写入输入框、连续不限时长及中英文/方言混说；macOS 2.2.0 与 Windows 2.1.0 又加入去口水词、标点分段、长内容归纳、语序整理等输出整理。[macOS 2.0.0](https://z.weixin.qq.com/web/change-log/144) · [macOS 2.2.0](https://z.weixin.qq.com/web/change-log/152) · [Windows 2.1.0](https://z.weixin.qq.com/web/change-log/153)
4. **快捷键属于语音输入主路径，不是隐藏的高级项。** macOS 2.0.0 直接以长按 `fn`介绍语音；Windows 2.1.0 直接以长按 `Ctrl+Win`介绍；macOS 2.2.2 又增加更多自定义快捷键支持。[macOS 2.2.2](https://z.weixin.qq.com/web/change-log/macos)
5. **VoicePaste 本轮不应新增组件库。** 现有 React 19.2 + Tailwind 4.2 + lucide-react + tw-animate-css 已足够实现侧栏、分组行、单选、原生选择框、密码输入、按钮和状态提示。完整引入 shadcn/ui、Radix Themes 或 Fluent UI 都会增加当前页面不需要的主题或依赖层。
6. **若以后出现 Dialog、Popover、Tooltip 等复杂焦点管理需求，优先按需采用 shadcn/ui。** 它的官方文档明确支持 React 19 与 Tailwind 4，并可继续使用 lucide；但本轮只借鉴结构和 token 思路，不安装。

## 3. 微信输入法桌面设置：可验证规律

### 3.1 信息架构

[Microsoft Store 官方产品页](https://apps.microsoft.com/detail/xpfffp686ndrdz?gl=CN&hl=zh-CN)“屏幕截图 2/4”可直接观察到：

- 左侧固定侧栏顶部显示产品标识，下方是纵向分类。
- 可辨认的分类包括“输入”“常用语”“外观”“快捷键”“跨设备”。
- 当前分类“输入”使用整行绿色底色高亮，不依赖微弱文字变色。
- 右侧内容区标题也是“输入”，形成“侧栏定位 + 页面标题确认”两级导航。
- 页面只展示当前分类，不使用当前 VoicePaste 式四个大卡片连续滚动。

**推断：** VoicePaste 也应按用户任务切换单页内容，而不是保留滚动目录、章节编号与 IntersectionObserver。当前功能量只需要 3 个分类：

1. **语音输入**：启动方式、全局快捷键、麦克风、麦克风测试。
2. **识别与词汇**：API Key、连接测试、热词。
3. **权限与状态**：快捷键、麦克风、自动粘贴状态与重试操作。

托盘运行说明放在侧栏底部即可；等真正有版本、帮助、隐私与许可入口时再增加“关于”，不为一个说明项单独建页。若 API Key 缺失，默认仍打开“语音输入”，但在页面顶部显示一条紧凑状态提示并链接到“识别与词汇”；不要让供应商配置取代用户的第一任务。

### 3.2 视觉密度

**直接观察：**

- 窗口主体是白色与很浅的冷灰色，侧栏和内容区通过明度、分隔线区分。
- 右侧设置以少量浅色圆角分组承载，多行控件共享同一容器。
- 单个设置行由左侧标签、必要时的短说明、右侧控件组成。
- 单选项、下拉框、开关都靠右排列，扫描路径稳定。
- 绿色主要用于当前侧栏项、选中状态和开关；大面积装饰色很少。
- 没有在每个分组上叠加明显投影，也没有章节数字、英文大写眉题或多层卡片套卡片。
- 官方截图能确认“紧凑但不拥挤”，不能据此推导真实字体、边距或控件像素值。

[官网桌面示意图](https://cdn.weread.qq.com/web/wetype/static/media/slide_cover_pc.48770fde5c4807b79a6b.png)也呈现窄侧栏、单内容面板、细分隔和大量空白，但它是示意图，只能作为方向印证。

**对当前 VoicePaste 的判断：**

当前设置页使用 `236px` 侧栏、四个 `max-w-[850px]` 大卡片、章节编号 `01–04`、多层边框与阴影，并大量使用 `9–12px` 文字。问题不是功能太多，而是容器和装饰层级太多、正文又偏小：视觉重量高，实际可读性反而低。

### 3.3 控件与交互模式

| 模式            | 第一方证据                                         | VoicePaste 可复用方式                                                    |
| --------------- | -------------------------------------------------- | ------------------------------------------------------------------------ |
| 侧栏分类        | Windows 设置截图使用整行高亮的纵向导航             | 4 个任务分类；图标只辅助识别，不替代文字                                 |
| 分组设置行      | “输入”页把多项单选、下拉与开关放入统一浅色分组     | 使用统一的“标题 + 若干分隔行”结构；不再每项单独成卡                      |
| 单选 + 尾部参数 | 输入法类型行左侧单选、右侧附加选择或设置入口       | 启动方式保留两项单选；选中状态同时用圆点、边框和文字表达                 |
| 即时开关        | 多个输入行为用右侧开关                             | 只用于真正二元且即时生效的设置；当前 VoicePaste 没有必要为了视觉新增开关 |
| 快捷键主路径    | macOS/Windows 更新说明把快捷键直接写入语音入口     | 快捷键位于“语音输入”首屏，不放到高级设置                                 |
| 连接/设备测试   | 微信截图未提供证据；VoicePaste 现有流程需要        | 作为对应字段右侧次级按钮；结果就地显示，不另开大提示卡                   |
| 保存            | 微信静态截图未显示保存按钮，不能推断其是否自动保存 | 保留 VoicePaste 显式保存语义，避免改变现有数据流                         |

Fluent 官方也明确建议：设置面板中的即时二元选项使用 Switch；布局中只保留一个主按钮；若不能自动保存，则使用 Save 并给出成功或错误反馈。[Fluent Button 使用指南](https://fluent2.microsoft.design/components/web/react/core/button/usage)

### 4.3 隐私与权限

[微信输入法隐私政策](https://z.weixin.qq.com/web/privacy)更新于 2026-05-11，明确说明：

- 语音转文字需要麦克风权限。
- 仅在使用功能期间上传语音到腾讯服务器实时处理。
- 返回文字结果后不储存输入的语音。
- 产品提供撤回授权、查看信息收集清单等路径。

**推断：** VoicePaste 的“权限与诊断”页也应把三件事说清楚：需要什么权限、何时使用、失败后怎么恢复。但处理方、存储方式和承诺必须依据 VoicePaste 自身真实实现编写，不能复制微信输入法隐私文案。

## 5. 候选组件方案对比

当前仓库基线：React `19.2.0`、Tailwind CSS `4.2.0`、lucide-react `1.30.0`、tw-animate-css `1.4.0`；未安装 `clsx`、`tailwind-merge`、`class-variance-authority`、Radix Themes 或 Fluent UI。

| 方案                                   | 官方事实                                                                                                                                                                                                                                                                                                                            | 与当前技术栈的工程推断                                                                                                                                       | 结论                                     |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------- |
| **现有 Tailwind + 原生 HTML + lucide** | 当前仓库已有完整样式与图标能力；原生 `input`、`select`、`textarea`、`button`、`radio` 足以覆盖现有设置                                                                                                                                                                                                                              | 无依赖、无 Provider、无第二套 token；可直接重排现有 Settings，保存和诊断逻辑不动                                                                             | **本轮推荐**                             |
| **shadcn/ui**                          | 官方明确所有组件已更新支持 Tailwind v4 与 React 19；手动安装使用 Tailwind、CSS 变量、`class-variance-authority`、`clsx`、`tailwind-merge`、lucide 和 tw-animate-css；`components.json` 可指定 lucide。[Tailwind v4 / React 19](https://ui.shadcn.com/docs/tailwind-v4) · [手动安装](https://ui.shadcn.com/docs/installation/manual) | 与现有栈最接近；已有 lucide 与 tw-animate-css，但完整接入仍要增加 CLI/工具包、三个 class 工具、CSS token 和组件源码。只做一个设置页时收益不足                | **未来复杂组件首选；本轮只借鉴，不安装** |
| **Radix Themes**                       | 官方安装 `@radix-ui/themes`，全局导入样式，并在根部包裹 `<Theme>`；通过 `accentColor`、`grayColor`、`radius`、`scaling`配置；亮暗模式开箱支持。[Getting started](https://www.radix-ui.com/themes/docs/overview/getting-started) · [Dark mode](https://www.radix-ui.com/themes/docs/theme/dark-mode)                                 | 表面只加一个包，但会引入预样式 CSS、Provider 和另一套主题语义；Tailwind 仍负责布局时会形成双样式系统。若按官方系统主题示例，还通常要增加 class 切换方案      | **不推荐**                               |
| **Fluent UI React v9**                 | 官方 React 资源指向 Fluent UI React v9；使用 `@fluentui/react-components`、`FluentProvider` 与主题；组件与指南覆盖设置页常见模式。[React overview](https://fluent2.microsoft.design/components/web/react) · [Develop](https://fluent2.microsoft.design/get-started/develop)                                                         | Griffel 运行时样式、Fluent token、Provider 和传递依赖会与 Tailwind 4 并存；lucide 与 Fluent 图标也会形成两套选择。除非产品明确采用 Fluent 视觉，否则成本最高 | **不推荐**                               |

### 5.1 为什么不是“先装 shadcn/ui 再改”

shadcn/ui 与现有栈最兼容，但当前页面没有 Dialog、Popover、Combobox、Menu 等需要复杂状态和焦点管理的控件。为 Button、Input、Select、Radio、Textarea 增加一层生成组件，只会把视觉改版变成依赖与 token 迁移。

最小策略：

1. 本轮继续使用现有 Tailwind 4 和 lucide-react。
2. 借鉴 shadcn 的中性色 token、统一圆角和 `data-*` 状态样式思路，但不复制整套 CSS。
3. 以后确实新增 Dialog、Tooltip、Popover 或可搜索 Select 时，再按组件逐个引入 shadcn/ui；不要一次安装完整组件集合。
4. 若只需要 class 合并，等出现真实动态 class 冲突再引入 `clsx`/`tailwind-merge`，当前模板字符串足够。

## 6. VoicePaste 最终推荐

### 6.1 页面骨架

第一轮保留当前 Tauri 设置窗口 `920 × 720` 与最小尺寸，避免把视觉改版扩成窗口行为改造。

```text
┌──────────────────────────────────────────────────────────┐
│  VoicePaste        │  语音输入                           │
│                    │  在任意输入框按快捷键开始说话       │
│  ● 语音输入        │                                     │
│    识别与词汇      │  ┌ 启动方式 ─────────────────────┐  │
│    权限与诊断      │  │ 按一下开始/结束        ○       │  │
│    关于            │  │ 按住说话，松开结束     ●       │  │
│                    │  └───────────────────────────────┘  │
│                    │  ┌ 快捷键与麦克风 ───────────────┐ │
│                    │  │ 全局快捷键        [⌘][⇧][Space]│ │
│                    │  │ 麦克风            [系统默认 ▾]│ │
│                    │  │                  [测试麦克风] │ │
│                    │  └───────────────────────────────┘ │
│                    │              恢复本页默认  保存  │
└──────────────────────────────────────────────────────────┘
```

建议规格均为 **VoicePaste 推断方案**，不是微信输入法像素复刻：

- 侧栏：`184–200px`，浅灰背景，右侧 `1px` 分隔线。
- 内容：单页滚动，左右 `32–40px`，正文最大宽度约 `620px`。
- 页面标题：`20–22px / 600`；说明 `12–13px`；设置标签 `13–14px`；辅助说明至少 `11–12px`。删除当前大量 `9px` 文案。
- 分组：白底或接近白底、`10–12px` 圆角、`1px` 浅边框；默认不使用投影。
- 设置行：最小高度 `52px`；有说明时 `60–64px`；行间用分隔线，不用每行独立卡片。
- 控件高度：输入框、选择框、主按钮统一 `34–36px`；图标 `14–16px`。
- 颜色：使用 VoicePaste 自有中性灰与现有紫色强调色；强调色只用于选中、焦点、主要动作和状态，不复制微信绿。

### 6.2 各页内容

#### 语音输入

页面说明：**“在任意输入框按快捷键开始说话，完成后自动粘贴。”**

1. **启动方式**
   - “按一下开始/结束”
   - “按住说话，松开结束”
   - 使用原生 radio 语义；整行可点；选中态同时显示圆点、边框和文字，不只靠颜色。
2. **全局快捷键**
   - 值用平台化 `<kbd>` 小键帽显示。
   - 编辑按钮文案：“点击后按下组合键”；录制态：“请按组合键，Esc 取消”。
3. **麦克风**
   - 原生 `<select>` 放右侧，默认项“系统默认麦克风”。
   - “测试麦克风”是次级按钮；音量条和“麦克风工作正常/失败原因”就在本行下方展开。

#### 识别与词汇

页面说明：**“配置识别服务，并提高姓名、产品名和专业词汇的准确率。”**

1. **API Key**
   - 标签直接写“火山引擎 API Key”，避免章节名只写“豆包语音”造成概念混淆。
   - 密码框尾部保留显示/隐藏按钮。
   - 帮助文案只解释用途：“用于连接语音识别服务。”系统钥匙串属于实现细节，不在主设置流程强调；若以后提供隐私或安全说明，再集中呈现。
   - “获取 API Key”作为字段下方的文本链接，不保留大面积紫色引导卡。
   - “测试连接”作为字段右侧或下方次级按钮，反馈就地显示。
2. **热词**
   - 标题：“热词”
   - 说明：“每行输入一个姓名、产品名或术语。”
   - 保留字符上限和去重规则，但压缩为一行辅助文案。

#### 权限与诊断

页面说明：**“确认快捷键、麦克风和自动粘贴是否可用。”**

- 每个能力一行：图标、名称、当前状态、必要操作。
- 状态例：“可用”“需要授权”“未检测”“浏览器预览不检查”。
- 状态同时使用图标与文字；颜色只作辅助。
- 仅失败项显示“重试授权”或平台设置入口；底部保留“刷新状态”。
- 加一段 VoicePaste 自身真实的数据处理说明；不得照抄微信输入法隐私承诺。

#### 应用说明

- 当前只在侧栏底部显示“关闭窗口后继续在系统托盘运行”。
- 等项目实际提供版本、帮助与反馈、隐私说明或开源许可入口时，再增加“关于”页。
- 不在所有页面底部重复平台和托盘文案。

### 6.3 保存与反馈

当前数据流是编辑后统一保存，因此不建议为了模仿静态截图改成自动保存。

- 内容区底部固定一条轻量操作栏。
- 只保留一个主按钮：“保存”。
- “恢复本页默认”只出现在“语音输入”页；“识别与词汇”把“清空常用词”放在字段内；诊断页不显示重置操作。API Key 不参与批量重置。
- 保存中：“保存中…”；成功：“设置已保存”；失败显示具体原因。
- 页面级错误靠近相关字段；只有跨页面保存错误才放全局提示。
- 按钮使用动词 + 必要名词：“保存”“测试连接”“测试麦克风”“刷新状态”，不写“确定”或“OK”。

## 7. 可参考与不可照搬

### 可参考的通用模式

- 窄侧栏 + 当前分类单页内容。
- 任务命名而非供应商或技术名词优先。
- 浅色分组、统一行高、右对齐控件。
- 一个主按钮，其他动作降级。
- 快捷键直接进入语音主路径。
- 权限、处理状态和恢复路径清楚可见。
- 选中/成功/错误状态同时用文字、图标和颜色表达。

### 不应照搬的品牌元素

- 微信输入法绿色、渐变绿色背景、Logo、`P` 图形或图标造型。
- “简洁、好用、打字快”等品牌口号及营销标题。
- 官方商店图中的插画、候选栏视觉、圆角比例和截图背景。
- 微信输入法的分类名称、功能文案、隐私承诺与默认快捷键。
- 为了“像微信”而加入 VoicePaste 没有的常用语、外观、跨设备或 AI 功能。

VoicePaste 应复制的是**层级纪律和视觉克制**，不是颜色、Logo 或功能表。

## 8. 最小落地顺序

不新增依赖，只调整现有设置组件和 Tailwind class：

1. 把滚动锚点侧栏改为 3 个页签状态；一次只渲染当前分类。
2. 删除章节编号、外层大卡投影、API Key 大引导卡和重复页脚。
3. 建立“页面标题 / 分组 / 设置行 / 辅助说明 / 操作栏”五级视觉结构。
4. 提升正文与辅助文字字号，统一输入框与按钮高度。
5. 保留现有加载、录制快捷键、麦克风测试、连接测试、诊断与保存逻辑；只迁移展示位置。
6. 使用现有 lucide 图标；导航图标最多 4 个，控件内部图标只在能增加辨识度时使用。
7. 暗色模式、主题切换、可拖动侧栏、动画导航和组件库迁移全部后置；有真实需求再做。
