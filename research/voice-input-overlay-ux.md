# 桌面语音输入悬浮窗 UX 调研

> 调研日期：2026-08-07  
> 范围：豆包输入法桌面端、闪电说桌面端；补充 Wispr Flow、Superwhisper 桌面端。  
> 基线：VoicePaste 当前悬浮窗为 `680 × 104`，水平居中、中心位于屏幕高度约 `72%`，实时文字最多显示两行并截断。

## 1. 证据口径

本文只采用产品官网、官方文档、官方发布仓库、官方更新日志及其中直接引用的官方图片。

- **直接观察**：官方页面中的实机截图或官方产品示意图可直接看到的内容。若只是示意图，会明确标出，不能当作运行时像素规格。
- **官方文字说明**：官方页面明确写出的行为、状态或操作。
- **推断**：由前两类证据导出的设计判断，不等同于竞品已实现事实。
- **未确认**：第一方材料没有提供足够证据；不使用第三方评测、普通用户视频补齐。

另需区分桌面与移动端：豆包官网中“语音待机 + 悬浮窗”图片旁明确标有“iOS 端专用”，因此不能用来证明桌面悬浮窗行为。[豆包输入法官网](https://ime.doubao.com/pc)

## 2. 摘要结论

1. **底部或屏幕边缘是证据最强的位置模式。** 豆包 macOS 官方营销图把语音控件放在目标文档下方、屏幕底部中央；Wispr Flow 官方文档明确称桌面 Flow Bar 是屏幕底部的浮动控件，并允许吸附到底、左、右边缘。[豆包 macOS 官方图](https://lf-speechfe-cdn.bytespeech.com/obj/speechfe-cdn/deploy/gaowujian/wave_site/241784/static/image/pc0.3662a368.png) · [Wispr Flow 桌面文档](https://docs.wisprflow.ai/articles/5096240724-navigating-the-wispr-flow-app-desktop-ios-and-android)
2. **桌面悬浮窗首先是状态与控制器，不是转写编辑器。** 豆包图只在悬浮条内显示波形；Wispr Flow 明确显示波形、Cancel、Stop；Superwhisper 显示波形、模式、停止、取消及状态点。三者第一方材料均未确认在桌面悬浮窗内持续展示多行实时全文。[豆包 macOS 官方图](https://lf-speechfe-cdn.bytespeech.com/obj/speechfe-cdn/deploy/gaowujian/wave_site/241784/static/image/pc0.3662a368.png) · [Wispr Flow 桌面文档](https://docs.wisprflow.ai/articles/5096240724-navigating-the-wispr-flow-app-desktop-ios-and-android) · [Superwhisper Recording Window](https://superwhisper.com/docs/get-started/interface-rec-window)
3. **波形是最一致的录音反馈。** 豆包、Wispr Flow、Superwhisper 都使用动态波形；Superwhisper 还用黄/蓝/绿状态点区分模型加载、处理中、完成。[Superwhisper Recording Window](https://superwhisper.com/docs/get-started/interface-rec-window)
4. **没有第一方证据支持“随文本无限增高”。** 已查材料没有公开桌面悬浮窗的实时文字容量、长文本滚动规则或随内容自动扩展规则。Superwhisper 的主窗/mini 窗是用户主动切换的形态，不是文本驱动的自动增高。[Superwhisper Recording Window](https://superwhisper.com/docs/get-started/interface-rec-window)
5. **VoicePaste 当前尺寸确实偏离“轻量状态条”方向。** `680 × 104` 更接近完整工具栏；用户已明确反馈遮挡感强。竞品没有统一像素值，但豆包与 Superwhisper mini 的直接观察都支持明显更紧凑的固定 pill。

## 4. 闪电说桌面端

## 8. VoicePaste 最小改动建议

以下均为基于上述证据的 **VoicePaste 设计推断**，不是对竞品未公开实现的事实陈述。

### 8.1 产品决策

1. **缩为固定 `420 × 64`。** 宽度足以容纳状态、约 18–24 个汉字的实时尾部预览和短波形，同时把占屏面积降到当前约 38%。
2. **实时文字保留一行。** VoicePaste 的流式回显是产品要求，不照搬豆包的“仅波形”；但 overlay 只显示刚说出的最新片段，不承担完整转写阅读。
3. **固定高度，不随内容扩展。** 长文本应落入目标输入框；自动增高会遮挡工作内容，并让控件在录音时持续跳动。
4. **默认放在可用工作区底部中央。** 底边距建议 `88 px`，横向至少留 `16 px`；相较当前屏幕高度 `72%` 的位置更接近豆包与 Wispr Flow 的底部状态条模式。

### 8.2 状态与溢出

1. **录音：** 麦克风/动态波形 + “正在听” + 最新一行文字；右侧只保留“松开完成”或“再次按下完成”的短提示。
2. **处理：** 保持同一尺寸，隐藏实时文字，显示 spinner + “正在整理…”；避免用户把尚未修正的流式文本误认为最终结果。
3. **成功：** 绿色勾 + “已输入”，停留约 `600–900 ms` 后淡出。
4. **错误：** 红色图标 + 一行可执行信息，例如“已复制，自动粘贴失败”，停留约 `2–3 s`。
5. **长文本：** 前端始终跟随文本尾部；左侧用渐隐或省略号表明前文存在。无滚动条、无换行、无自动扩高。

### 8.3 暂不实现

- 不做自由拖拽、边缘吸附、main/mini 双形态；这些可在真实遮挡反馈出现后再加。
- 不显示完整实时全文；目标输入框与最终粘贴结果才是全文承载面。

## 9. 推荐规格表

| 项目      | 推荐规格                                                         | 理由                                                                                  |
| --------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 位置      | 水平居中；底边距可用工作区底边 `88 px`；左右最小安全边距 `16 px` | 豆包官方图与 Wispr Flow 都指向底部/边缘；缩小后置底不会像当前大窗那样压住工作区中心。 |
| 宽度      | `min(420 px, workAreaWidth - 32 px)`                             | 足够显示短状态与一行中文，显著小于当前 `680 px`。                                     |
| 高度      | `64 px` 固定                                                     | 接近状态 pill，而非工具栏；不因长文本抖动或遮挡。                                     |
| 形态      | 深色横向 pill；圆角约 `24–28 px`                                 | 延续当前视觉语言，避免重做品牌样式。                                                  |
| 实时文字  | 最新 **1 行**，约 18–24 个汉字                                   | 保留流式反馈；闪电说官方示意也采用单行片段，豆包/Superwhisper mini 则更克制。         |
| 溢出策略  | 自动跟随尾部；左侧渐隐/省略号；无滚动条                          | 用户最关心刚说出的内容，完整文本不应撑大 overlay。                                    |
| 录音状态  | 动态波形 + “正在听” + 最新片段                                   | 波形是豆包、Wispr Flow、Superwhisper 的共同模式。                                     |
| 处理状态  | spinner/呼吸点 + “正在整理…”；隐藏流式片段                       | 明确区分第一遍识别与最终修正。                                                        |
| 成功状态  | 绿色勾 + “已输入”，`600–900 ms` 后淡出                           | 确认完成但不打断连续输入。                                                            |
| 取消/错误 | `Esc` 取消；错误只显示一行可执行信息                             | 保持控件紧凑，避免错误详情撑高窗口。                                                  |
| 自动扩展  | **关闭**                                                         | overlay 是状态控制器，不是转写编辑器。                                                |

## 10. 最终建议

本轮建议：**把 `680 × 104` 改为固定 `420 × 64`，移到可用工作区底部中央，只显示最新一行实时文字，永不随文本增高。**

这是对当前“太大、不好看”反馈的直接修正，也保留 VoicePaste 区别于纯波形工具的流式回显。拖拽吸附、完整大窗和更多文本行先不做；真实用户反馈证明仍有需要时再加。
